## 3.4.8：工具箱两个转换工具重写（commit ff865b66）

**起因**：用户问「工具箱那几个转换格式的工具需要重写吗」，拆包核实后发现是功能级 bug。

**关键发现（重要）**：`com.arthenica:ffmpeg-kit-*` 已从 Maven Central **全部下架**（6.0-2 与 6.0.LTS 的 aar/pom 都 404，arthenica.github.io 仓库也 404），本地只剩 `ffmpeg-kit-min` 缓存。后果：① 新克隆/CI 根本构建不出来（之前新建的 release.yml 必挂）；② min 包 grep `libavcodec.so` 无 `libmp3lame`/`libvorbis`，所以旧代码里 MP3、OGG 两个选项**一直是必失败**的死选项（FLAC/WAV/AAC 有原生编码器）。
**结论**：彻底移除 ffmpeg，改平台编解码。MP3/OGG/FLAC 只能放弃——纯 Java 的 LAME 移植（jump3r）API 依赖 `javax.sound.sampled`，Android 没有，走不通。

**改动**：
- 新增 `data/convert/`：`ConvertModels`（ImageTarget/AudioTarget/ConvertException/ConvertedFile/AAC_MIME）、`OutputTargets`（SAF 优先、MediaStore IS_PENDING 收尾、失败删半成品）、`ImageConverter`、`AudioConverter`。
- `ImageConverter`：先 inJustDecodeBounds 算 inSampleSize（长边 4096 上限），读 EXIF 转正（8 种方向），JPG/BMP 铺白底，**手写 24 位 BMP 编码器**（旧代码 `else -> JPEG` 把 JPEG 字节存成 .bmp）。
- `AudioConverter`：M4A = MediaExtractor+MediaMuxer 原样搬 AAC 轨（无损、秒级、不复制整片）；WAV = MediaCodec 解码 PCM + 手写 RIFF 头（先占位 44 字节再回填）；进度用 sampleTime/presentationTimeUs，取消靠 `currentCoroutineContext().ensureActive()`。
- 新增 `ui/util/MediaActions.kt`（打开/分享/复制位置），DownloadsScreen 三个私有函数改为委托。
- 新增 `ui/screens/ConvertCommon.kt`：`ConvertPage` 统一页骨架 + 进度条 + 成品行；两个页面共用。
- 图片转换支持批量（GetMultipleContents，上限 30 张）、缩略图预览、逐张进度；视频转音频改成「先选视频看信息 → 再点开始提取」。
- 版本 3.4.8 / 401，更新日志 6 条已写入 recentLogs。
