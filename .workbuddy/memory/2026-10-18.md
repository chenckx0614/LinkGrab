## LinkGrab v3.0.14（文叔叔显示不全根治）

用户反馈：点工具箱「文叔叔」后页面一部分是灰块/白块、图片或列表缺一半；同一手机用系统浏览器打开是完整的。前几版都在调 UA / viewport / 缓存，方向错了。

- **根因一（主因）**：`AppNavigation` 的 `liquidBackdrop` 从 2.5.23 起挂在**整个 NavHost** 上（`!transitioning` 时常挂），WebView 页面也被录进 GraphicsLayer。WebView 走 Chromium functor 合成，被录制后只能拿到部分帧 → 灰块/白块、图片列表缺一半。3.0.12 只修了**页面内菜单**的采样层（Column→顶栏 Row），NavHost 这层一直没动。改为 `recordNavBackdrop = !transitioning && onMainTabs`（采样层只为底栏玻璃存在）。
- **根因二**：`IOSPageSurface` 的 `blur(18dp*cover)` + `Modifier.shadow` 外壳套在所有 iosPage 上，WebView 被包在 RenderEffect/graphicsLayer 里会局部不重绘。新增 `WebViewHostRoutes = {game, tool_web}`，这两页跳过外壳直接渲染。
- **加载闸门**：`loadUrl` 挪到 `addOnLayoutChangeListener` 尺寸 > 0 之后（`post{}` 兜底）。理由：文叔叔 `<head>` 里按 `window.innerHeight` 算 `--vh`，0×0 时算出 0，`height:calc(var(--vh)*100)` 的容器整块塌陷（3.0.8 观察到的「只剩客服球/☰/打开App 横幅」就是这个）。
- `onPageFinished` + 视口尺寸变化时补发 `resize` 事件（`DispatchResizeJs`），让站点用真实 innerHeight 重算 `--vh`。
- 工具页设置：`loadWithOverviewMode=false`、去掉 `setSupportMultipleWindows(true)`（开着不实现 onCreateWindow 会吞 window.open/target=_blank）、白底垫层、淡入结束摘掉 alpha 合成层。
- **补齐 `onShowFileChooser`**（`rememberLauncherForActivityResult` + `ActivityResultContracts.StartActivityForResult`）：之前网页 `<input type=file>` 点了毫无反应，等于文叔叔不能上传。
- 版本号升到 3.0.14（versionCode 315），更新日志 + CLAUDE.md 版本表已更新；`dist/LinkGrab-3.0.14-{arm64-v8a,armeabi-v7a}.apk`。
- 编译验证：`./gradlew assembleRelease` 成功；`gh` 在本机不可用（GitHub Release 需另配）。

## LinkGrab v3.0.15（文件传输二级页 + 菜单玻璃 + 视口自愈）

用户三件事：① 工具箱加「文件传输」二级页收多家服务 ② 右上角菜单毛玻璃不要影响网页（之前加模糊就闪）③ 文叔叔还是显示不全。

- **菜单毛玻璃**：`rememberCanvasBackdrop`（backdrop 库 `CanvasBackdrop`，DrawScope 是**局部坐标**，`LayerBackdrop` 自己 `translate`，CanvasBackdrop 不 translate —— 反编译 classes.jar 确认）画一张「开菜单瞬间截的 200×380dp 网页区域」位图。截图区域 = 面板矩形（宽 200dp、右边距 16dp、顶边 topInset+8dp），网页从 topInset+58dp 开始，先把顶栏底色铺满再按位移画网页。玻璃里是真页面模糊，死图永不干扰网页。顶栏的 `layerBackdrop(headerBackdrop)` 删除。
- **文叔叔显示不全**：用 headless Chrome + CDP（`websocket-client` 已装，Chrome 需 `suppress_origin=True` 绕 403）实测：
  - 站点**响应式**：`html` inline font-size = `innerWidth` 推算（390→39px，800→54px 封顶），`resize` 会重算；`screen.width` 被伪造也不影响 → 只吃 `innerWidth`。
  - 390×844@2.75 移动仿真渲染完整；窗口 390 但初始布局 800 时 rootFont 卡在 54 → 内容超出视口 → **只剩左半屏**（第一次截图的假象是窗口尺寸导致的，不是站点固定 750）。
  - 结论：WebView 报给页面的 `innerWidth` 一旦偏宽（初始宽视口/尺寸未定），整页就按错宽度排版 → 视口自愈 `buildFitViewportJs(cssWidth)`：`innerWidth > 视图宽×1.08` → meta 改 `width=<视图宽>, initial-scale=1`；内容超视口 → shrink-to-fit 缩放；改完 120ms 补发 resize。`onPageFinished` 0/400/1200ms 各跑一次 + 视口尺寸变化时跑。
  - **注意**：Chrome 移动仿真下运行时改 meta 不一定立即生效（`Emulation` 覆盖），WebView 真机行为待验证；所以同时提供「页面诊断」。
- **页面诊断**（菜单第三项）：evaluateJavascript 回传 kernel Chrome 版本、视图宽、innerWidth/Height、doc scrollW/H、root font、--vh、图片加载数、节点数；`org.json.JSONTokener` 解转义；面板可选中复制。后续用户截图即可定位。

## LinkGrab v3.0.19（能力扩展 A：B站 / 微博 / 网页 / 二维码 / 音乐多源）

用户「可以把 a 全做」——A 是我上一轮列的「内容能力」五件。

- **B站**（`BilibiliParser`）：`bilibili.com/video/BV…`、`av123`、`b23.tv` 短链 → `x/web-interface/view`（title/pic/cid/owner）→ `x/player/playurl` 取 **progressive durl**（不是 DASH）。实测 2026-10：匿名 `quality=64`（720P）带音轨 mp4，`upos-sz-estgoss.bilivideo.com`，带 `Referer: https://www.bilibili.com/` 后 Range 请求 206。接口必须带 Referer/Origin + 随机 `buvid3` cookie，否则 412。番剧走 `pgc/view/web/season` + `pgc/player/web/playurl`（多数要登录）。
  - **为什么不用 DASH**：`fnval=4048` 的 dash 视频/音频是两条流，只下 video 会得到无声文件；合并要改「一任务一 URL」的队列 → 留后续。
- **微博**（`WeiboParser`）：访客校验 `passport.weibo.com/visitor/genvisitor` → `visitor?a=incarnate`（OkHttp 内存 CookieJar）→ `m.weibo.cn/statuses/show`；兜底解析详情页 HTML 的 `var $render_data`。**实测本机网络访客校验被拦（返回 Sina Visitor HTML、无 Set-Cookie）**，所以做成 best-effort + 明确提示「微博拦截了匿名访问」。
- **通用网页**（`GenericWebParser`）：og:video/twitter:player:stream → `<video src>`/`<source>` → JSON-LD contentUrl → og:image → 正文 `<img>`（过滤 avatar/icon/logo 等，去重取 12 张）。`Platform` 新增 `WEB`：**任何 http(s) 链接都算可解析**，不再报「不支持」。
- **二维码**：首页「二维码」按钮 → 相册选图 → `com.google.zxing:core:3.5.3`（纯 Java，0.5MB）解码，>1200px 先缩放省内存；解出的文本再过 `supportedLinkIn` 抽链接直接解析。**不做相机预览**（免 CAMERA 权限，截图分享码场景已够）。
