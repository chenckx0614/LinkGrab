## LinkGrab v3.0.14（文叔叔显示不全根治）

用户反馈：点工具箱「文叔叔」后页面一部分是灰块/白块、图片或列表缺一半；同一手机用系统浏览器打开是完整的。前几版都在调 UA / viewport / 缓存，方向错了。

- **根因一（主因）**：`AppNavigation` 的 `liquidBackdrop` 从 2.5.23 起挂在**整个 NavHost** 上（`!transitioning` 时常挂），WebView 页面也被录进 GraphicsLayer。WebView 走 Chromium functor 合成，被录制后只能拿到部分帧 → 灰块/白块、图片列表缺一半。3.0.12 只修了**页面内菜单**的采样层（Column→顶栏 Row），NavHost 这层一直没动。改为 `recordNavBackdrop = !transitioning && onMainTabs`（采样层只为底栏玻璃存在）。
- **根因二**：`IOSPageSurface` 的 `blur(18dp*cover)` + `Modifier.shadow` 外壳套在所有 iosPage 上，WebView 被包在 RenderEffect/graphicsLayer 里会局部不重绘。新增 `WebViewHostRoutes = {game, tool_web}`，这两页跳过外壳直接渲染。
- **加载闸门**：`loadUrl` 挪到 `addOnLayoutChangeListener` 尺寸 > 0 之后（`post{}` 兜底）。理由：文叔叔 `<head>` 里按 `window.innerHeight` 算 `--vh`，0×0 时算出 0，`height:calc(var(--vh)*100)` 的容器整块塌陷（3.0.8 观察到的「只剩客服球/☰/打开App 横幅」就是这个）。
- `onPageFinished` + 视口尺寸变化时补发 `resize` 事件（`DispatchResizeJs`），让站点用真实 innerHeight 重算 `--vh`。
- 工具页设置：`loadWithOverviewMode=false`、去掉 `setSupportMultipleWindows(true)`（开着不实现 onCreateWindow 会吞 window.open/target=_blank）、白底垫层、淡入结束摘掉 alpha 合成层。
- **补齐 `onShowFileChooser`**（`rememberLauncherForActivityResult` + `ActivityResultContracts.StartActivityForResult`）：之前网页 `<input type=file>` 点了毫无反应，等于文叔叔不能上传。
- 版本号升到 3.0.14（versionCode 315），更新日志 + CLAUDE.md 版本表已更新；`dist/LinkGrab-3.0.14-{arm64-v8a,armeabi-v7a}.apk`。
- 编译验证：`./gradlew assembleRelease` 成功；`gh` 在本机不可用（GitHub Release 需另配）。
